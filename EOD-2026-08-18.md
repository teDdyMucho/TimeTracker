## 1. Xero — Custom Connection, connected & verified ✅ (the big one)
- **Root problem:** the app in Xero is a **Custom Connection** (machine-to-machine), but our code used the standard OAuth2 redirect flow with a different app (`171DA…`). That mismatch caused `invalid_scope — Client credentials scope validation failed`.
- **Reworked the integration** to the Custom Connection model: `client_credentials` grant, no user-redirect login. Neutralised the old `connect`/`callback` OAuth routes; "Connect Xero" now just links the authorised org's tenant to the entity.
- **Scopes trimmed to the minimum needed:** `payroll.employees.read` + `payroll.settings.read` (read-only). The Xero app was reconfigured to match.
- **Authorised by Chris** (chris@buildonedesignconstruction.com.au) → org **ARKO Joinery Pty Ltd** connected.
- **Set the real Custom Connection credentials** (Client ID `D894…`, Client secret 2) in `.env.local` — the old `171DA…` id was the mismatch.
- **Verified live:** token acquired, connected org read, **8 employees** and **13 earnings rates** (Ordinary Hours, Overtime, Public Holiday, Saturday, Sunday Overtime, Tool Allowance, etc.) pulled successfully. Both entities (ARKO + Build One) show as Connected. Payroll Preview works (shows hours mapped to Xero pay bands; nothing is pushed — read-only).

Currently **read-only** (read employees + rates, preview the mapping); an actual auto-push would need write scopes and re-approval.
