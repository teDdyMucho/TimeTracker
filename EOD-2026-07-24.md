## 3. Admin — Reset employee password (no current password needed) ✅
Enhancement so an admin can reset a locked-out/forgetful employee's password.
- On **Employees → Edit**, added a **"Reset password (optional)"** field with an **eye icon inside the box** to show/hide.
- Leave blank = password unchanged; type a new one = the employee's sign-in password changes immediately.
- **The employee's current password is NOT required** — uses Supabase's service-role Auth admin API (`auth.admin.updateUserById`), the same privileged client already used to create employees. Minimum 6 characters, validated on form + server.
- Files: `admin/app/(dashboard)/employees/edit-employee-form.tsx`, `admin/app/(dashboard)/employees/actions.ts`. No migration/rebuild — deploys on next push (Netlify).

## 4. Xero permissions — client clarification (drafted reply)
The client's accountant (Chris) asked why the app needs Payroll Admin access to Xero and what data it reads/stores/modifies.
- Verified in code: the integration is currently **read-only** (all `xeroGet` calls) — it reads Organisation name, Employees, and PayItems only, to map our logged hours to the right employee/earnings rate. **No writes, and it never touches bank details or personal pay info.**
- Drafted an honest reply explaining this and offering to reduce the requested Xero scopes to the minimum (the broad `payroll.*` scopes are Xero's own permission grouping, not something the app fully uses).
