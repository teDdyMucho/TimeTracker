# End of Day — 29 September 2026
**Project:** Timevera (BuildOne) Time Tracker — Admin Portal + Mobile App

---

## Summary
Full audit of why the client receives no notifications. The Expo pipeline itself is healthy — verified with real delivery receipts to all 10 stored tokens. The problem was that almost nothing was being sent. Fixed server-side, so it works on every phone as-is with no app update.

---

## 1. Audit: what is NOT broken
- Sent an invisible data-only push to all 10 stored tokens: **10/10 delivered** per Expo receipts. Tokens, FCM/APNs credentials and the send path are fine.
- Push registration works — 10 of 16 active profiles have a token.
- Admin approval pushes (attendance / leave / overtime) were reaching phones.

## 2. Root causes found
1. **Worker → admin events notified nobody.** A worker's message, overtime request or leave request produced no push and no inbox row. If the client tested by messaging the office, silence was the designed behaviour.
2. **Nightly auto clock-out never pushed** — it wrote an in-app inbox row only.
3. **The app's own notification inserts were silently rejected** — `notifications` had no INSERT policy for phones (found 18 Sep, fixed now).
4. **Local reminders never fired before 7.2** (untyped-trigger bug, fixed 23 Sep); 7.2+ is not on phones yet.
5. Expo ticket errors were discarded unread by the sender.

## 3. Fixes — live, no app build needed (`dfe42c1`, migration `0020`)
- **An inbox row now equals a phone push:** AFTER INSERT trigger on `notifications` delivers via Expo (pg_net, async, best-effort — a push failure can never block the insert).
- **Worker events fan out to every active admin:** message, overtime request, leave request → inbox row + push.
- **Auto clock-out now pushes** the worker via the same mechanism.
- **INSERT policy** so the app can write its own notifications.
- Removed the three explicit admin pushes the trigger now duplicates; sender logs Expo rejections.
- Netlify redeployed.

## 4. Testing
- Fan-out verified for all three worker events in rolled-back transactions (4 and 8 admin rows created, nothing real sent).
- Full insert → trigger → Expo HTTP chain proven end to end with a throwaway token (Expo returned the expected "not a registered push token"); token and test rows cleaned up.
- **Not yet confirmed by a real person on a real phone** — no genuine push has gone through since the trigger went live.

## 5. Remaining gaps on the worker side (phones, not code)
- **6 profiles have no push token** — Harvey Jacklin, Mitchell Baldry, Ronald Abraham, Build One Employee, and 2 of the 3 Robbie Wynne profiles. They receive nothing until they open the current app and allow notifications.
