# End of Day — 18 September 2026
**Project:** Timevera (BuildOne) Time Tracker — Admin Portal + Mobile App

---

## Summary
Client reported that the app "stopped registering hours and scrapped the profile picture", that workers must sign out every night, and asked that the app **stay logged in the whole time**. Traced it to three separate causes. One is fixed and live on the server; the other two are fixed in **mobile v1.0.5**, built for both platforms but **not yet released or tested on a real phone**.

---

## 1. Server-side auto clock-out — live ✅
- **Problem:** the 12h auto clock-out only ran inside the app, while it was open and signed in. A worker who signed out (or never reopened the app) kept an open session forever and no timesheet was written — the shift was lost.
- **Fix:** `0017_auto_clock_out_cron.sql` — a `pg_cron` job runs nightly at **00:00 Brisbane** (14:00 UTC) and closes any session open past 12h: clock-out = clock-in + 12h, a 12h `submitted` timesheet on the original `work_date`, and a notification. Same 12h cap as the app (client's choice).
- **Verified on the live database:** rollback-only test (20h session closed at exactly 12h, 2h session untouched, no double-logging on a second run) and a temporary every-minute probe confirmed the scheduler fires. No test data left behind.
- No mobile build needed — it works for every installed version.

## 2. Mobile v1.0.5 — blank home screen / "stay logged in" ⏳ built, not released
- **Root cause A:** after the OS killed the app overnight, the profile was fetched once; if that failed (weak site signal) it stayed null with nothing to fall back on → "Welcome back, there", 0h, no timesheets, and Clock Out silently did nothing. Only signing out and back in recovered it.
- **Root cause B (the actual screenshot):** nothing waited for the saved login to be restored. With an expired token, the refresh outlasts the ~2s splash, so Home rendered with no session behind it for up to ~30s.
- **Fixes:** profile cached on the device and shown immediately; profile sync retried in the background (de-duplicated, result dropped if the user signed out meanwhile); Home's hours and Clock Out keyed on the session user id; pull-to-refresh recovers a missing profile; a branded "Signing you in…" screen covers startup and is guaranteed to clear (try/finally, 35s and 8s ceilings).
- **Also fixed (pre-existing):** Face ID lock re-triggered on every hourly token refresh; now locks on launch only.
- **Two review passes found defects in my own first version** and fixed them: profile retry was blocking sign-in/token refresh; a redundant session retry could freeze startup ~90s offline; a late write could undo a sign-out.
- **Testing:** real `auth.ts` run against 11 simulated scenarios — 18/18 pass (the old v1.0.4 code fails 9/13, reproducing the reported blank state). Metro bundle builds. **Not run on a physical device.**
- Server check: no session has a forced expiry, so the server is not logging anyone out.
