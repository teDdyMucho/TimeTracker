## 3. Duplicate-timesheet race ✅ fixed in 7.3
- `writeClockOut` guarded the session update with `clocked_out_at is null` but inserted the timesheet even when the update matched nothing. Tapping Clock Out as the app auto-closed the session → session closed once, **two timesheets**. Present in all versions incl. 7.2.
- Found in production data (24 Sep):
  - **Ronny Abraham** — 13.63h + 12.00h (`3b9c2d8b…` is the duplicate)
  - **Robbie Wynne** — 16.17h + 16.00h (`975c1a54…` is the duplicate)
- Fix: only the call that actually closed the session writes the timesheet. Covers clock-out, auto clock-out and switch project (`c536e2b`).
- Tested with a guard-faithful fake DB, manual + auto clock-out at once: **old code 2 timesheets (reproduces Ronny), new code 1**. 16h harness still 10/10. Not tested on a device.
